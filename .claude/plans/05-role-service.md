## 2. Objective

The Role Service will manage roles and permissions within the e-commerce platform, providing a centralized way to define user roles (e.g., ADMIN, USER) and their associated metadata.

## 3. Existing Context

The Role Service is a provider service. It is consumed by the User Service (for assigning roles to users) and the Auth Service (for including roles in JWT tokens).

## 4. Scope

### In Scope
- Role CRUD operations (Create, Read, Update, Delete).
- Enforcement of unique role names.
- Implementation of Repository and DTO patterns.
- Global exception handling for 404, 409, and 400 errors.
- Unit, Controller, and Integration tests.

### Out of Scope
- User management (handled by User Service).
- Authentication and JWT generation (handled by Auth Service).
- Complex PBAC (Permission-Based Access Control) - deferred to later phases.

## 8. API Implementation Plan

### List All Roles
- HTTP method: `GET`
- path: `/api/roles`
- request DTO: N/A
- validation: N/A
- response DTO: `List<RoleResponseDTO>`
- status codes: `200 OK`, `401 Unauthorized`, `403 Forbidden`
- authentication/authorization: `ROLE_ADMIN`
- downstream calls: None
- error behavior: Return empty list if no roles exist.

### Get Role by ID
- HTTP method: `GET`
- path: `/api/roles/{roleId}`
- request DTO: N/A
- validation: UUID format for `{roleId}`
- response DTO: `RoleResponseDTO`
- status codes: `200 OK`, `404 Not Found`
- authentication/authorization: Internal or `ROLE_ADMIN`
- downstream calls: None
- error behavior: Throw `RoleNotFoundException`.

### Create Role
- HTTP method: `POST`
- path: `/api/roles`
- request DTO: `RoleRequestDTO` (name, description)
- validation: `name` (NotNull, NotBlank, pattern `ROLE_.*`)
- response DTO: `RoleResponseDTO`
- status codes: `201 Created`, `400 Bad Request`, `409 Conflict`
- authentication/authorization: `ROLE_ADMIN`
- downstream calls: None
- error behavior: Return 409 if role name exists.

### Update Role
- HTTP method: `PUT`
- path: `/api/roles/{roleId}`
- request DTO: `RoleRequestDTO` (name, description)
- validation: `name` (NotNull, NotBlank)
- response D favorite: `RoleResponseDTO`
- status codes: `200 OK`, `404 Not Found`, `400 Bad Request`
- authentication/authorization: `ROLE_ADMIN`
- downstream calls: None
- error behavior: Throw `RoleNotFoundException`.

### Delete Role
- HTTP method: `DELETE`
- path: `/api/roles/{roleId}`
- request DTO: N/A
- validation: UUID format for `{roleId}`
- response DTO: N/A
- status codes: `204 No Content`, `404 Not Found`, `409 Conflict`
- authentication/authorization: `ROLE_ADMIN`
- downstream calls: None
- error behavior: Return 409 if role is assigned to users.

## 9. Service Layer Plan

1. **List Roles**: Retrieve all `Role` entities and map to `RoleResponseDTO`.
2. **Get Role**: Retrieve `Role` by ID. Map to `RoleResponseDTO`.
3. **Create Role**:
    - Validate role name uniqueness.
    - Validate name pattern (`ROLE_`).
    - Save `Role` entity.
4. **Update Role**:
    - Verify role exists.
    - Update metadata and save.
5. **Delete Role**:
    - Verify role exists.
    - Perform hard delete (or soft delete if decided later).

## 10. Design Pattern Implementation Plan

### Repository Pattern
- Where: `RoleRepository`
- Why: Standard JPA abstraction.
- Main participants: `RoleRepository` extending `JpaRepository`.

### DTO Pattern
- Where: `RoleRequestDTO`, `RoleResponseDTO`
- Why: Prevents exposing internal entity and audit fields.
- Main participants: `RoleRequestDTO`, `RoleResponseDTO`.

## 11. Remote Communication Plan

No remote calls are made by the Role Service.

## 12. Exception Handling Plan

- **RoleNotFoundException**: Thrown when `roleId` is not found. Maps to 404 Not Found.
- **RoleAlreadyExistsException**: Thrown when creating a duplicate role name. Maps to 409 Conflict.
- **Global Exception Handler**: Uses `@RestControllerAdvice` to map exceptions to a standardized error response shape: `{ "error": "...", "id": "..." }`.

## 13. Security Plan

- **Authentication**: Handled by API Gateway via JWT.
- **Authorization**: `ROLE_ADMIN` required for all modification endpoints.
- **Sensitive Data**: None.
