## 2. Objective

The Category Service will manage the product categorization system, providing the ability to create categories and organize them into a hierarchical tree structure using the Composite pattern, allowing products to be grouped logically for browsing and filtering.

## 3. Existing Context

The Category Service is a leaf service in the current dependency graph. It is consumed by the Product Service (Port 8081) for aggregated product views.

## 4. Scope

### In Scope
- Category CRUD operations (Create, Get).
- Implementation of the Category hierarchy tree (Composite pattern).
- Enforcement of unique category names.
- Implementation of Repository and DTO patterns.
- Global exception handling for 404 and 400 errors.
- Unit, Controller, and Integration tests.

### Out of Scope
- Managing products (handled by Product Service).
- Managing inventory (handled by Inventory Service).
- User-specific category preferences.
- Complex search/filtering of categories.

## 8. API Implementation Plan

### Create Category
- HTTP method: `POST`
- path: `/categories`
- request DTO: `CategoryRequest` (name, parentCategoryId)
- validation: `name` (@NotBlank)
- response DTO: `CategoryResponse`
- status codes: `200 OK`, `400 Bad Request` (duplicate name or invalid parent)
- authentication/authorization: ADMIN
- downstream calls: None
- error behavior: Return 400 Conflict if category name exists.

### Get Category
- HTTP method: `GET`
- path: `/categories/{id}`
- request DTO: N/A
- validation: UUID format for `{id}`
- response DTO: `CategoryResponse`
- status codes: `200 OK`, `404 Not Found`
- authentication/authorization: Public
- downstream calls: None
- error behavior: Throw `CategoryNotFoundException`.

### Get Category Tree
- HTTP method: `GET`
- path: `/categories/tree`
- request DTO: N/A
- validation: N/A
- response DTO: `List<CategoryNode>`
- status codes: `200 OK`
- authentication/authorization: Public
- downstream calls: None
- error behavior: Return empty list if no categories exist.

## 9. Service Layer Plan

1. **Create Category**:
    - Validate that the category name is unique.
    - If `parentCategoryId` is provided, verify it exists.
    - Save the `Category` entity.
2. **Get Category**:
    - Retrieve `Category` by ID.
    - Map to `CategoryResponse`.
3. **Get Category Tree**:
    - Retrieve all categories from the database.
    - Build a nested tree structure using `CategoryNode` DTOs.
    - Return only the root categories (those where `parentCategoryId` is null).

## 10. Design Pattern Implementation Plan

### Composite Pattern
- Where: `CategoryNode` DTO and `CategoryServiceImpl.getCategoryTree()`
- Why: To represent the part-whole hierarchy of categories and subcategories.
- Main participants: `CategoryNode` (Composite object containing a list of children).
- Expected behavior: A single API call returns the entire hierarchy.

### Repository Pattern
- Where: `CategoryRepository`
- Why: Standard JPA abstraction.
- Main participants: `CategoryRepository` extending `JpaRepository`.

### DTO Pattern
- Where: `CategoryRequest`, `CategoryResponse`, `CategoryNode`
- Why: Separates internal entity from API contract.
- Main participants: `CategoryRequest`, `CategoryResponse`, `CategoryNode`.

## 12. Exception Handling Plan

- **CategoryNotFoundException**: Thrown when `categoryId` is not found. Maps to 404 Not Found.
- **Global Exception Handler**: Uses `@RestControllerAdvice` to map exceptions to a standardized error response shape: `{ "error": "...", "id": "..." }`.

## 13. Security Plan

- **Authorization**: `POST /categories` requires `ADMIN` role. Public access for `GET` endpoints.
- **Sensitive Data**: None.
